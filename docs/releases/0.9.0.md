# SDK 0.9.0

Version 0.9.0 of `@sempods/client-sdk`, `@sempods/app-sdk` and
`@sempods/app-ui`. These notes describe the changes since 0.8.0. The release
has the same content as the prerelease `0.9.0-dev.4`. Install it with exact
versions, the UI kit only when the app uses it:

```sh
npm install --save-exact @sempods/client-sdk@0.9.0 @sempods/app-sdk@0.9.0 @sempods/app-ui@0.9.0
```

The [migration guide](../migration.md#from-080-to-090) has the upgrade step
for each change.

## Breaking changes

- **New required members** break typed test doubles and exhaustive object
  literals: `ContextView.values`, `AppSnapshot.starting`, `ContextChoice.label` and `contextLabel`,
  `PodContextChoice.podLabel` and `podUrl`, `PodContextGroup.label`,
  `FieldUpdateRow.timestamps` (also on `ContextUpdateRow`), and
  `setPriority` on the loader that `createViewLoader(pod, …)` returns for a
  `BoundPod`, `Pod.findFlat` and `BoundPod.findFlat`, and
  `FindGraph.observations`.
- **Find `nodes` are normalized.** They are built from the RDF the answer
  encodes: flattened, `@type` and every value an array, and a node that
  states nothing is left out
  ([migration](../migration.md#find-observations-the-flat-form-and-a-type-filter)).
- **`connect` and `authorize` reject with `RuntimeError('storage')`** when the
  target's previous sign-out or forget could not be saved; retry that first.
  `runtime.connect(url)` now waits for a pending sign-out for any Pod, not only
  the configured default, and can reject the same way.
- **`runtime.connect(url)` reuses a matching connection** for any Pod; use the
  returned connection's ID rather than expecting a new one per call.
- **Restoration renews a credential that is due.** An expired grant goes
  `restoring` → `ended` without passing `active`, one without a refresh token
  ends `expired`, and restoration can take up to 20 seconds longer than its
  discovery.
- **The `react` entry imports `react-dom`** (an optional peer, like `react`)
  for the startup screen's portal.
- **`AppAccess` looks and behaves differently at startup and sign-in.** A
  startup screen covers restoration and the first catalogue, and the Context
  surface and prompts wait for it; `startup="none"` leaves the restoration
  screen to the app, but the access card's "Loading…" no longer shows. With
  several saved Pods the last active one is chosen.
- **End-to-end tests of the sign-in need new steps.** The Pod address is a
  combobox prefilled with `https://sempods.org/` when no targets are
  configured, so typing appends; **Forget** is now **Remove from this device**
  inside **Manage saved Pods**. Recovery comparisons show "No value" instead
  of "—" ([migration guide](../migration.md#simpler-appaccess-sign-in)).
- **New default messages.** `createLocale` fills English and German defaults
  for eleven new optional `controls` messages, and `podHint` and `loginHint` are
  no longer empty. An app that translates the controls into another language
  adds them; one that set `forget` also sets `removeSavedPod`.
- **Several tabs share their sessions.** A second tab of the app starts
  `durable` instead of `busy`, and `SessionLocks.request` is also called
  without `ifAvailable`, with `mode` and `signal`: an injected `locks` must
  wait for a held lock until `signal` aborts. An injected `openStore` whose
  store has no `watch` keeps one active tab as before
  ([several tabs](../browser-runtime.md#several-tabs)).
- **A failed re-authorization keeps the session.** A failed callback that
  consumed its attempt reports `failed` with `resumed: true` instead of
  ending the connection; check `resumed === true` before using the earlier
  session, since a callback that waited too long for another tab's lock
  reports `failed` (`coordination`) without it. The default
  `controls.sharingUnchanged` text says that the change was not confirmed
  ([migration](../migration.md#re-authorization-keeps-the-session), #393).
- **Pods & sharing management is grouped by Pod.** Its **Active pod**
  select, the separate **Sign out** button and the collapsed **Connect
  another Pod** are gone: each Pod has a row whose **⋯** button holds its
  actions, **Sign out on this device** among them, and connecting another
  Pod is a step of the dialog. `controls.canChange` now reads **Can edit**
  ([migration](../migration.md#pods--sharing-grouped-by-pod), #386).
- **Default colours are sage** in the UI kit's fallback palette, the TODO
  example and every app-sdk fallback token, with outlined primary actions in
  the SDK surfaces. App theme files still override them; the migration guide
  lists the 0.8.0 values.

## Access and sessions

- **Several active tabs.** The app's tabs share one durable session per
  connection and stay usable side by side. A refresh is claimed under the
  connection's Web Lock and compare-and-swap, so its token is sent once; the
  other tabs read the stored result. A renewal, a new sign-in, a sign-out and a
  forget reach every tab through a `BroadcastChannel`; Context selection and
  drafts stay per tab. A refresh whose tab closed before its answer is resent
  once by another tab within the grace period. A reload keeps the tab's own
  Context choice (`tabStorage`), and a Pod another tab signed in to is listed
  and reused by `connect()`, so one Pod keeps one saved connection.
  `SessionStore.watch` is the store's new optional member for this
  ([several tabs](../browser-runtime.md#several-tabs), #374).
- **Re-authorization keeps the session.** **Change sharing** and any other
  sign-in of a signed-in connection store their attempt beside the session,
  which keeps working in every tab until a validated callback replaces it. A
  failed callback keeps the session too
  ([upgrade steps](../migration.md#re-authorization-keeps-the-session), #393).
- **Several Pods without signing in.** Under `signIn: 'optional'`,
  `runtime.connect(url)` (`useApp().connect(url)`) adds further Pods beside
  the default one. Each has its own catalogue, labels and `bindPod` handle
  and reads without a token. Signing in to one leaves the others reading
  without a token. With the default `rememberPods: true`, the address of such
  a Pod is saved without discovery, client or token. The next start and the
  app's other tabs list it as `signed-out` (without a `problem`) until
  `forget(id)`, and **Pods & sharing** offers **Remove from this device** for
  it. A resolved `connect()` does not confirm the save: when the write fails
  or another tab holds that Pod's lock for more than three seconds, the Pod
  reads in the current page only, and the next start does not list it unless
  a later operation saves it. Signing in replaces the address with the session; a first sign-in
  that fails, or is signed out of before it completes, puts the address
  back. With `rememberPods: false`, the Pod is listed in the current page
  only. Such an address does not prevent `firstSignIn: 'silent'`, unless it
  is the address of the default Pod itself
  ([apps without sign-in](../browser-runtime.md#apps-without-sign-in), #372).
  An SDK without this record kind (such as 0.9.0-dev.3) reports a saved
  address in `StartupReport.unreadable` and leaves it untouched; after a
  downgrade the Pod is not listed until the app is upgraded again.

- **Silent first sign-in (opt-in).** A deployed `did:web` app in front of one
  Pod sets `firstSignIn: 'silent'`: with nothing stored on the device, startup
  asks the Pod once per tab with `prompt=none`, and a person with a session
  and a grant there is signed in without a click. `login_required`,
  `consent_required` and `interaction_required` leave the connection signed
  out without an error, and `StartupReport.firstSignIn` names the cause. The
  Pod's `error_uri` on its own origin reaches the UI as
  `AccessPrompt.providerLink`, a link beside **Sign in**; its free text stays
  dropped. `prepareAuthorization` accepts `prompt: 'none'` and
  `OAuthFailure.providerLink` carries the link for apps that build their own
  flow ([silent first sign-in](../browser-runtime.md#silent-first-sign-in)).
- **Change sharing asks for consent.** **Change sharing**, **Share more …**
  and `useContexts().share()` ask the Pod for its consent page
  (`prompt=consent`) even when it could reuse the app's grant, which a
  deployed `did:web` app's sign-in does. Own sharing controls pass
  `authorize(id, { intent: 'change-sharing' })`; a plain sign-in, startup
  restoration and renewal still reuse the grant
  ([changing sharing](../react-authoring.md#changing-what-the-app-may-access)).
- **Startup screen.** `AppAccess` shows `AppStartup`, one calm screen with the
  app's icon and name, from the saved records to the first catalogue a
  Context needs, with the content mounted and inert behind it.
  `useAppState().starting` tells an app the same. The screen takes the
  `--sempods-*` tokens and `color-scheme` from where `AppAccess` is placed
  ([startup screen and static splash](../react-authoring.md#startup-screen-and-static-splash)).
- **The last active Pod at startup.** With several saved Pods the app
  controller makes the one the app last worked with active, remembered in
  `preferences`. One that ended, is unreachable, lacks a required scope or
  still restores after 5 seconds gives way to a Pod that works
  ([several Pods at startup](../browser-runtime.md#several-pods-at-startup)).
- **Simpler sign-in.** The default sign-in centres the app above one editable
  Pod chooser that holds the saved Pods and their management, and one main
  action. `podAddressPrefix` sets the start of a new address. Help appears on
  request. Custom connection views get `surface`, `podAddress` and
  `podAddressPrefix`, and `AccessGate` accepts `components.Connections`
  ([custom connection views](../react-authoring.md#replacing-the-connection-view)).
- **Pods & sharing by Pod.** Management lists each Pod in a labelled row:
  its name opens what the app may do there, loaded when it opens, and a 44px
  **⋯** button named for the Pod holds **Change sharing**, **Use this Pod**
  (a guarded switch) and **Sign out on this device**, or **Sign in**,
  **Remove from this device** and **Try again** for a signed-out or
  unreachable Pod. The selected Pod is marked **Selected**; an app that shows
  several Pods at once sets `podView="combined"` and may describe the view
  with `podViewDescription`. **Connect another Pod** opens the sign-in's
  chooser as a step of the same dialog
  ([Pods & sharing management](../react-authoring.md#pods--sharing-management),
  #386).
- **One redirect at a time.** While any Pod's sign-in or **Change sharing**
  redirect is pending, not only the selected Pod's, the content is inert,
  management shows only that the sign-in opens, guarded actions such as
  `useContexts().share()` resolve `false`, a leave prompt still open is
  cancelled and `selectTarget` reports `blocked`. Selecting the Pod or
  Context that is already selected still resolves `true`. A redirect that
  does not leave within three seconds, because the browser stopped it or the
  person stayed in a leave prompt, offers **Stay on this page**, which
  abandons the attempt through the new `cancelAuthorization(id)` of
  `useApp()` and `BrowserRuntime`; before, a stopped sign-in of the selected
  Pod kept the content inert until a reload
  ([selection and draft lifetime](../react-authoring.md#selection-and-draft-lifetime),
  #386).
- **`PodChooser`** puts the sign-in's Pod chooser where a multi-Pod app adds
  another Pod while signed in: the address prefix, the saved Pods and their
  management, the same keyboard use and labels. Matching a typed address,
  restoring Pods and failed sign-outs stay with the SDK
  ([adding another Pod](../react-authoring.md#adding-another-pod-while-signed-in)).
- **Remembered Pods once.** Concurrent `connect` calls share discovery, and
  startup cleans up redundant address-only records from older SDKs
  ([connection reuse](../browser-runtime.md#one-known-pod)).
- **Settings before sign-in.** `settings` on `AppAccess` and `AccessGate`
  puts a corner button in the gate that opens the app's own settings, such
  as language and appearance
  ([settings before sign-in](../react-authoring.md#app-settings-before-sign-in)).
  The gate shows again, with the focus kept, when a browser closes it on a
  repeated Escape.
- **Focus after SDK dialogs.** Closing Pods & sharing or an access prompt by
  keyboard returns the focus with its visible ring, because React now sees
  the focus arrive.
- **Focus after an access action.** A control of the access surface that its
  own action disables while it runs, such as **Check access**, gets the focus
  back once the action ends. WebKit moved it to the page and left it there.
- **Plain choices in `AppAccess` `settings`** show one per 44px row: a
  `fieldset` with radio or checkbox labels needs no app CSS in the settings
  dialog, as the guide promised.

- **Shared notification host (opt-in).** `<Notices />` shows the app's own
  notices and the access prompts in one bounded stack at the bottom of the
  viewport, outside the document flow; while it is mounted, `AppAccess` shows
  no prompt stack of its own, and without it `AppAccess` is unchanged.
  `useNotice(notice | null)` holds a notice while its state lasts and retires
  it with its cause; `useNotices()` shows and dismisses one by key. A notice
  has localized text, an optional title, `info`, `warning` or `error`, one
  optional guarded action and a duration: brief information hides after about
  6 seconds, warnings, errors and notices with an action stay. Repeats of a key
  coalesce, each event is announced once, nothing takes the focus, Escape
  dismisses, timers pause on hover and focus, and the motion respects reduced
  motion. The stack waits while a modal covers the page, shows app notices
  inside the sign-in gate before sign-in, and stays inside the visual
  viewport, above the safe area and elements marked
  `data-sempods-notices-avoid`. `components={{ Notice }}` replaces the
  renderer; the host keeps the guards and the lifecycle, and a confirmation
  the renderer opens stays open while the stack waits under it, keeps its
  Escape and its slot, and closes when a new event replaces its notice.
  `accessPrompts={false}` leaves the access prompts where they were, and the
  stack stays above them. The
  [authoring guide](../react-authoring.md#app-wide-notices) says when to use a
  notice, inline recovery or a blocking prompt (#385).

## Reads and editing

- **Signing out of another Pod keeps the selected view's work.** `disconnect`
  and `forget` of a connection that is not the active one leave, and wait
  for, only the work bound to it. SDK forms and editors name their
  connection through the new optional `LeaveGuard.connectionId`; an app's own
  `useDraftGuard` with the `connection` or `explicit` scope is still asked
  about ([selection and draft lifetime](../react-authoring.md#selection-and-draft-lifetime),
  #386).
- **Priority in place.** `usePodLoad({ priority })` and `loader.setPriority`
  move a loader's waiting reads ahead or back under `podReadLimit` without
  restarting them ([bounded Pod reads](../browser-runtime.md#bounded-pod-reads)).
- **Structured values in recovery comparisons.** `ResourceEditor`'s review
  and `UpdateNotice` show text variants with their language, lists and nested
  values instead of `[object Object]`, and tell "No value" from "Empty text".
  Optional `valueLabels` name enumerated values there as the app's form
  does, such as `status: 'open'` as "Offen"; unlisted values show as before
  ([notices](../react-authoring.md#notices-updatenotice)).
- **Creation and modification times.** `fields(spec, { timestamps })` lets
  the standard writes maintain them outside the draft; `timestampsOf(row)`
  reads them for ordering ([guide and recipe](../timestamps.md)).
- **A confirmed tick orders by its own time.** `row.timestamps` of
  `useFieldUpdate` and `useContextUpdate` lays the modification instant a
  confirmed update wrote over the read ones until the list reads the row
  again, as `row.data` does for its values; `updateFields` returns it as
  `saved.modified`. Pending, refused, conflicting and unconfirmed writes keep
  the instants as read, and the timestamps recipe orders rows as shown
  ([before the list reads again](../timestamps.md#before-the-list-reads-again),
  #387).
- **Editor actions in confirmation order.** `ResourceEditor` puts **Delete**
  first, set apart at the start of its row, then **Check again** while
  blocked, and ends with **Cancel** (or **Discard changes**) and **Save**, in
  DOM order, as the SDK's confirmations and `DialogFooter` do. Long labels
  wrap inside the dialog
  ([migration](../migration.md#resourceeditor-actions-in-confirmation-order),
  #401).
- **Rows and editors of several connected Pods.** `useContextUpdate().for`
  and `useContextEditor().open` take the `connection` a row was read from:
  it is written or edited there with its own evidence, without selecting
  that connection or switching the active Pod. Its recovery and leave guard
  stay with that connection, `unresolved` entries name it, and connection
  actions ask only about work of the connection they act on, and sign-ins,
  which leave the page, about all of it
  (`LeaveGuard.connection`;
  [rows of several connected Pods](../react-authoring.md#rows-of-several-connected-pods),
  #408).
- **`rdf:langString` literals.** `selectTextVariant` and `patchTextVariant`
  also read a language literal that states its implied type.
- **Find observations, the flat form and a type filter.** `find` keeps its
  grouped answer and moves the Pod's optional `sps:findResult` observations
  (excerpt, position, engine) out of `nodes` into typed `observations`, with
  each statement's Context. `findFlat` reads one graph without Contexts, and
  `types` filters hits by exact `rdf:type` on the Pod. Both read the answer
  by the RDF it encodes, so `nodes` come in one canonical, flattened form
  whatever the serialization. Grouped answers with statements outside a
  named Context reject. New in `0.9.0-dev.4`
  ([finding resources](../../packages/client-sdk/README.md#finding-resources),
  [migration](../migration.md#find-observations-the-flat-form-and-a-type-filter),
  #418).
- **One value at a time.** `ContextView.values` reads one predicate's values
  with the slot's tag, adds one value, replaces or clears them, and removes
  one IRI value through the Pod's slot and edge routes, without a
  whole-resource read or a merge patch. Value writes return the slot's new `etag` and the Pod's
  `outcome` on `applied`
  ([one value at a time](../../packages/client-sdk/README.md#one-value-at-a-time)).

## UI kit

- **`ContextSwitch`** is the standard Context chooser grouped by Pod, with
  guarded selection, Pod recovery and a **Read only** mark; recovery actions
  apply to their own Pod. It only selects: changing what is shared stays in
  `AppAccess`, and sharing appears only on a loaded Pod that shares nothing
  readable. Since `0.9.0-dev.3` it has no permanent sharing action, address
  details or icon legend, and `texts.shareMore`, `showAddresses` and
  `addresses` are gone; name the remaining action with `shareContexts`
  ("Share lists …"). Choosers read the concise `contextLabel`, a
  `qualifier` that tells equal names in one Pod apart, and `podLabel`
  ([the chooser guide](../react-authoring.md#one-chooser-across-pods)).
  Optional `texts` replace each of its messages that says "context", such as
  loading, empty and unavailable, with the app's own noun in its language.
  With a single connected Pod its trigger shows only the Context; the Pod
  line appears once there is a second Pod to choose.
- **The compact `Dialog`'s corner Close** is a 44px target around the same
  glyph; a header placed directly in it keeps room for it.
- **`DialogFooter` keeps its actions inside the dialog** in one row at every
  width, Cancel left and the answer right as in the SDK's confirmations,
  wrapping actions and, if needed, labels instead of overflowing; its buttons
  are 44px targets. A long unbroken name breaks inside `Dialog`. The README
  shows a short confirmation from these parts
  ([README](../../packages/app-ui/README.md#components), #368).
- **`ScreenDialog`** is full screen below 640px wide or 480px high, so a
  phone in landscape with the keyboard open can still scroll to its fields
  and actions. Below 320px high its heading scrolls with the content.
- **`SuggestField` address mode.** `suggest={false}` keeps the suggestions
  closed and unannounced for text the app does not search, such as an exact
  address or a single character, in the same input with Enter submitting;
  `ref` reaches the input, for example for Ctrl/Cmd-K.
- **A visual and a notice for `SuggestField`.** A suggestion's optional
  `media`, such as a photo or a type icon, shows in a 40px box before the
  label, hidden from assistive technology; `notice` is the app's own quiet
  line about its search under the open suggestions, not announced. The
  field's status line no longer gets cut off below a long, scrolling list
  ([README](../../packages/app-ui/README.md#adapters),
  [migration guide](../migration.md#a-visual-and-a-notice-for-suggestfield)).
- **One voice for `SuggestField`'s suggestions.** React Aria no longer
  announces "0 options available" while the first search runs, nor repeats
  the counts the field announces itself, also on a busy page; the field's
  status stays the only announcement of its searches and results.
- **`HeaderMenu` labels in another language.** `lang` on a choice or an
  action marks its label, so a language named in itself ("Deutsch" in an
  English menu) is read in that language; the name stays the label.
- **A menu opened again while it is still closing takes the focus.** A
  `HeaderMenu` or `DropdownMenu` whose item opened a `Dialog` that was
  answered at once, before the menu's exit animation ended, opened again
  without focus, arrow keys or Escape. Each opening now mounts a new popup,
  which ends the old one's exit; a menu closed otherwise keeps its exit
  animation. An app that suppressed the exit animation while a kit modal is
  open can drop that CSS (#391).

- **SDK questions above an open overlay.** The SDK's modal dialogs stay out
  of the `inert` marks that React Aria sets around the UI kit's `Dialog`,
  `ScreenDialog` or a popover, so Playwright 1.65 and later can click them
  with a plain `click()`; the background stays inert behind the modal dialog
  ([migration guide](../migration.md#sdk-questions-in-playwright-165-and-later)).
- **`Checkbox`** ticks a list row: a 20px box in a 44px target with a check
  mark, from the aria-nova registry
  ([README](../../packages/app-ui/README.md#components)). The target grows
  with the root font size like the box and a `size-11` control (about 49.75px
  at `html { font-size: 112.5% }`); apps need no change, and a box enlarged
  through `className` keeps working.
- **Current links.** `nav.link(place)` adds `aria-current="page"` to a link
  to the shown place, compared by the router's canonical address (path and
  query), so an app no longer compares places next to each link. A `ghost`
  link (`buttonVariants`, `ActionLink`) that carries it is drawn chosen under
  every action variant: the `muted` surface, `foreground` text and an
  underline. An app's element drawn with `buttonVariants`, such as a view
  link, now gets the kit's solid 2px focus outline instead of the 50% ring
  alone, which stayed below 3:1. The theme check gains the pair `foreground`
  on `muted`
  ([views as links](../../packages/app-ui/README.md#views-as-links),
  [migration guide](../migration.md#current-view-links-from-the-router)).
- **Views on one baseline.** A second
  [README recipe](../../packages/app-ui/README.md#views-on-one-baseline)
  draws routed view links as a strip with the current one barred on its
  baseline, counts in the links and a ghost icon action beside the `nav`. It
  uses only `nav.link`, theme roles and utilities, and the UI gate runs it by
  touch, pointer and keyboard in forced colours (#384).
- **Ghost actions stay transparent without Preflight.** `Button`,
  `LinkButton`, `ActionButton` and `HeaderMenu` in the `ghost` variant rest
  without a surface also when the app imports only Tailwind's theme and
  utilities; the browser's gray button face no longer shows (#392).
- **`InlineTextEdit`** renames one text value in its row, such as a shopping
  item, without the full `ResourceEditor`: a controlled input with Save and
  Cancel that writes nothing itself. Moving between its controls keeps it
  open, a press beside it or Tab past it asks the app to dismiss, a pending
  write keeps it locked, and Save, Cancel or Escape can return the focus to
  the trigger, also after a slow save. The app keeps the trigger, the draft
  and its policy, validation and the write through `useFieldUpdate`
  ([recipe](../react-authoring.md#renaming-one-value-in-a-row),
  [README](../../packages/app-ui/README.md#renaming-in-a-row), #394).
- **`DateChoice`** is the calendar-day choice without a trigger, for an
  app's own dialog such as a `ScreenDialog`: localized presets with
  concrete days select in one activation, `min` disables earlier days and
  presets without hiding them, and a custom day from the calendar or typed
  as `YYYY-MM-DD` waits for Apply. A typed day that does not exist or comes
  before `min` is marked invalid and disables Apply; nothing is corrected.
  Enter in the typed entry submits no form and saves no editor around it.
  `DateChooser` shows the same choice in its popover and gains `presets`,
  `min` and the typed entry
  ([README](../../packages/app-ui/README.md#a-date-choice-in-a-screen-dialog),
  [migration guide](../migration.md#presets-a-minimum-and-typed-days-in-date-choosers),
  #400).
- **`DeleteIcon`** is the shared delete glyph, Lucide's `Trash2` at 1rem and
  always decorative. `RemoveButton` without children now shows the same
  outline at 1rem instead of its own 20px glyph, so a row's delete and a bulk
  action match without an app icon import
  ([delete actions](../../packages/app-ui/README.md#delete-actions),
  [migration guide](../migration.md#the-shared-delete-icon), #389). Its new
  `question` names what the row deletes, for example the same title in two
  Contexts.
- **Markdown for long text fields.** The opt-in entry
  `@sempods/app-ui/markdown` reads and writes Markdown text with
  `MarkdownView` and `MarkdownField`; its renderer and editor are optional
  peers that only apps using it install
  ([Markdown text](../../packages/app-ui/README.md#markdown-text), #395).

## Recipes

The recipes are code to copy from `examples/todo/recipes`, not package
exports; an app that copied one copies it again for a change.

- [RDF neighbourhoods](../neighborhood.md): a bounded first page per Pod and
  direction that also samples the relationship kinds it does not show.
- [Public RDF](../public-rdf.md): a dataset lookup that keeps the graph each
  statement comes from.
- [Resource cards](../resource-cards.md) no longer show facts read with an
  earlier grant after a grant change on the same connection.
- [Clearing done tasks across a Pod](../react-authoring.md#several-rows-from-one-decision):
  `clear-done-overview.tsx` deletes the done tasks of every writable Context
  after one confirmation with the counts by area and the read-only rows kept,
  and keeps a stopped row's recovery once it leaves the view. Its question
  and summary start afresh with another Pod or authorization. It shares the run, its summary (with why a command sent nothing)
  and the compact dialog with `clear-done.tsx`, which now uses that dialog and
  a `RemoveButton` per row (#389).

The [PWA guide](../pwa.md#colours-and-system-ui) now explains how manifest,
launch and page colours relate to the app's theme.

The PWA recipe's `NewVersionNotice` publishes the waiting update through
`useNotice` instead of a paragraph in the page, and the [PWA
guide](../pwa.md#with-vite-the-quickstart-app) mounts `<Notices />` beside it (#385).

## Evidence and limits

The changes are covered by unit and fixture tests against a loopback fixture
Pod. Several Pods without sign-in run in one process instead: an injected
`fetch` in place of the Pods, `fake-indexeddb` as the session store and
