# SDK 0.8.0 (in preparation)

These notes collect the changes for 0.8.0 of `@sempods/client-sdk`,
`@sempods/app-sdk` and `@sempods/app-ui`. The prerelease `0.8.0-dev.1`
carries all of them under the npm dist-tag `next`, for testing apps against
the new packages; `latest` stays 0.7.0 until 0.8.0 is released. Install it
with exact versions, the UI kit only when the app uses it:

```sh
npm install --save-exact @sempods/client-sdk@0.8.0-dev.1 @sempods/app-sdk@0.8.0-dev.1 @sempods/app-ui@0.8.0-dev.1
```

The [migration guide](../migration.md#from-070-to-080) has the upgrade step
for each change.

## Breaking changes

- **Custom session stores** (`openStore`) need the new required method
  `SessionStore.remove(id, expectedRevision)`.
- **`disconnect(id)` keeps the connection** as `signed-out` with
  `problem: 'disconnected'`; `forget(id)` removes it, as `disconnect` used to.
  Connection lists (`useAppState().connections`, `useConnections()`,
  `usePodContexts()`) now include remembered Pods.
- **`format.dateOnly` and `format.dateTime` return `string | undefined`**
  instead of throwing. In JSX, `{format.dateTime(value)}` still compiles and
  renders nothing where a `catch` showed the stored value: use
  `format.dateTime(value) ?? value`. `format.dateTime` now reads a string only
  as a zoned `xsd:dateTime` on a real day, and both show years 0001 to 9999
  only.
- **A renewal whose outcome stays unknown** beyond the grace period ends as
  `interrupted`, keeping the Pod address; 0.7 ended it with `exchange`.
- **New required members** break typed test doubles, custom `podFactory`
  results and exhaustive `switch` statements: `AppSnapshot.access` and
  `signIn`, `BrowserRuntime.signIn` and `forget`, `AppActions.forget`,
  `Connection.reading`, `Pod.find` and `BoundPod.find`, and the reason
  `'anonymous'` of `AccessPrompt`.
- **End-to-end tests** find sign-in controls in the gate
  (`[data-sempods-ui="gate"]`) instead of the `Pods & sharing` region, see no
  initial loading panel, and in a German app find the compact `Dialog`'s close
  button as "Schließen".

`AppSnapshot.callbackNotice` is deprecated and stays until 1.0.

## Access and sessions

- **Remembered Pods.** Sign-out and an ended session keep the connection with
  its address as `signed-out`, also after a reload, so people sign in again
  with one action; `rememberPods: false` opts out
  ([remembered Pods](../browser-runtime.md#remembered-pods)).
- **Access prompts.** `AppAccess` shows a sign-in gate above the mounted
  content while the app cannot work, and outcomes such as a cancelled sign-in
  or an unreachable Pod as dismissible prompts. `AccessGate`, `ContextAccess`,
  `AccessPrompts`, `useAccessPrompts` and `AppAccess only="management"` let an
  app place them itself
  ([access prompts](../react-authoring.md#access-prompts-and-your-own-placement)).
- **Lost renewal answers.** When the answer to a renewal is lost, its refresh
  token is sent once more within `refreshGracePeriod` (default 60 seconds),
  so the session continues instead of ending. A renewal's token request is
  given up after 20 seconds
  ([lost renewal answers](../browser-runtime.md#lost-renewal-answers)).
- **Bounded discovery.** A Pod whose discovery does not answer within 15
  seconds no longer keeps a saved session `restoring`: it ends as
  `ended { problem: 'network', restorable: true }`, and `connect(url)` and
  `beginAuthorization(id)` reject with `RuntimeError('network')`
  ([browser runtime](../browser-runtime.md#configure-initialize-connect)).
- **Apps without sign-in.** `signIn: 'optional'` reads public data first and
  offers signing in; `signIn: 'none'` never signs in and needs no `identity`
  ([apps without sign-in](../browser-runtime.md#apps-without-sign-in)).
- **Captured work.** Drafts and unresolved writes outlive an ended session also
  in explicit Contexts and while their screen is hidden or unmounted; opening
  the same row again returns to its work.

## Reads

- **Bounded Pod reads.** `podReadLimit: { perPod?, total? }` limits the
  explicit Pod reads in flight, and `priority: 'current'` lets the read the
  person looks at go first
  ([bounded Pod reads](../browser-runtime.md#bounded-pod-reads)).
- **Reads per connection.** `usePodLoad(pod, read, options?)` reads through an
  explicit `BoundPod`, for example the same resource from every connected Pod
  ([reads per connection](../react-authoring.md#reads-per-connection)).
- **Find.** `pod.find(text, options)` and `BoundPod.find` search a Pod; the
  answer groups the matching statements by source Context, so one resource can
  appear in several groups
  ([finding resources](../../packages/client-sdk/README.md#finding-resources)).

## Dates

- **One classification of stored dates.** `classifyDate` in
  `@sempods/client-sdk/edit` tells a calendar day, an instant with a time zone
  and an unsupported value apart; the `date` and `dateTime` fields, the
  formatters and `DateChooser` use it.
- **Four-digit years.** The formatters show years below 1000 with four digits
  (`01.03.0050`, not `01.03.50`).

## UI kit

- The compact `Dialog` takes the SDK's language for its close label
  (`closeLabel` sets another) and stays open when an SDK confirmation above it
  is answered.
- `ScreenDialog` keeps clear of device safe-area insets on phones; remove app
  CSS that added them, or they count twice.
- `HeaderMenu` takes a `ref` to its button, which an app passes to `AppAccess`
  as `focusTarget` so focus returns there, and a decorative `icon` per action.
- Menus keep the keyboard focus ring visible and drop it after a pointer
  dismissal.
- `DateChooser` shows a value that names no real day, or that the `date` field
  rejects, as stored.
- `SuggestField` is a search or address bar with suggestions the app finds as
  the person types, on the new `Combobox` from shadcn/ui: keyboard and
  screen reader behaviour from React Aria, announced loading, empty and
  failed searches, and Enter to submit typed text
  ([UI kit guide](../../packages/app-ui/README.md#adapters)).
- `@sempods/app-ui` names `@sempods/client-sdk` of the same minor version as a
  peer dependency.

## Recipes

- [RDF values](../rdf-values.md): readable text, exact terms, dates and web
  addresses for values a SPARQL read returns.
- [Resource cards](../resource-cards.md): cards with pictures and dates from
  every connected Pod, with the source of each value and bounded reads.
- [Public RDF](../public-rdf.md): one explicit, credential-free lookup of an
  IRI's own RDF document, kept apart from Pod data.

## Evidence and limits

The changes are covered by unit and fixture tests against a loopback fixture
Pod. The packed runtime and todo consumers run in Chromium; the UI kit's
browser gate runs in Chromium and WebKit, and in Firefox on Linux CI. Reading
without sign-in is tested without a browser. Nothing in this release has been
checked against a deployed Pod or on real devices, including:

- resending a lost renewal answer against a Pod with a grace period;
- reading public data from an origin outside the Pod's CORS allowlist;
- Find, the discovery deadline and `podReadLimit` against a real Pod;
- `usePodLoad` with an explicit `BoundPod` in a multi-Pod app;
- `ScreenDialog` insets and the menu focus ring on real phones;
- installed PWAs on iOS and iPadOS.
