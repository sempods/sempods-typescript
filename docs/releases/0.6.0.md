# SDK 0.6.0

Version 0.6.0 of `@sempods/client-sdk` and `@sempods/app-sdk` simplifies app
authoring and preserves editing work across React screen lifetimes. These notes
describe the changes since 0.5.0.

## What changes for app authors

- **One row mutation pattern.** Selected-Context lists and Pod overviews both use
  `mutate.for(item)` for commands, availability and recovery notices. Typed
  creation uses `useCreation` or `bindCreation`, with a collection or a fixed IRI.
- **Work survives React screen lifetimes.** Editors and dispatched write lanes
  belong to the controller. A remount or an Activity hide retains drafts, pending
  saves, uncertain outcomes and their leave guards. Reopening the same resource
  recovers its editor; app-local selection and unsent creation drafts still have
  their own lifetimes.
- **Calmer loading and access.** Lists keep rows during refresh. Cancelled
  re-authorization preserves a valid session; offline startup can restore it
  later. Deep links can survive sign-in. SDK texts follow the browser language
  by default.
- **Less app plumbing.** `useContexts`, `useMessages`, `LoadNotice`,
  `UnresolvedNotices` and `RemoveButton` cover common app behavior. `usePodList`
  and `useContextUpdate` compose an overview with writes in each row's Context.
  App layouts, visual identity and domain interactions stay app-owned.
- **A clearer starting point.** The template and the installed
  [AI app-builder guide](../ai-app-builder.md) lead into one working screen;
  advanced contracts remain references. The quickstart and examples use the
  same public API.

## Upgrade from 0.5.0

This is a breaking 0.x minor release. Follow the
[migration checklist](../migration.md#from-050-to-060), especially removal of
`AppShell`, `ConnectionControls` and hook-level row commands, explicit `not-sent`
results, creation addressing, structured failure details and changed UI defaults.
Both packages must have version **0.6.0**. There was no published 0.5.1.

The runtime reads 0.5 session records. A re-authorization saved by 0.6 can retain
an earlier session; downgrading that storage to 0.5 is unsupported. A deployment
rollback does not roll back Pod data or browser storage.

## Verification and limits

Automated coverage includes SDK tests, installed-package consumers, Chromium
runtime fixtures and generated template apps. These checks use Node 24.15.0,
the SDK's pnpm 11.1.2 and the template's pnpm 11.28.2. Check the
[support matrix](../../README.md#supported-environments)
for unchanged browser, React and PWA requirements.

Packed Chromium/runtime tests use fixtures; they do not establish a real-Pod
login, deployed large-catalogue behavior, installed-device support or the quality
of an unfamiliar person's first app. Those remain separate evidence:
[deployed-Pod validation #52](https://github.com/sempods/sempods-typescript/issues/52),
[independent app-author exercise #74](https://github.com/sempods/sempods-typescript/issues/74)
and the [PWA device checklist](../pwa.md).
